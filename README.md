# travel

## 여행지 추천 툴 (`index.html`)
단일 파일 · 오프라인 · 모바일 우선. 브라우저로 `index.html`을 열면 바로 동작합니다 (데이터는 localStorage).

- **추천**: 두 사람의 마지막 근무 → 출발지·출발시각, 복귀 후 첫 근무 → 귀가 마감·자동 박수, 테마 슬라이더 11축 → 국내 상위 5 + 해외 슬롯
- **기록**: 장면별(가는 길·현지 이동·먹기·자기·하기·날씨·돈·휴식·해외) 체크 → 축별 배수 m + 여행지 속성 감점 자동 계산
- **데이터**: JSON export / import(스키마 검증 + 변경 diff 미리보기 + 직전 상태 자동 백업 1개)
- **설정**: 근무 시각, 버퍼, 배수 상수(1.5 / 1.3 / 보정상수), 활동시간 임계값 등

### 파일 구조
| 경로 | 역할 |
|---|---|
| `index.html` | 앱 본체. `<script id="core">` = 계산 코어(순수 함수), `<script id="seed-data">` = 시드 데이터(인라인) |
| `data/seed.json` | 시드 여행지 정본 (국내 60 · 거점 12 · 해외 17). 점수·소요시간·속성(attrs)은 **초안 추정치** |
| `tools/build.js` | `data/seed.json` → `index.html` 인라인 (`node tools/build.js`) |
| `tools/gen-seed.js` | 최초 시드 생성기 (기록용. 이후엔 seed.json 직접 수정) |
| `tests/core.test.js` | 수식 검증값·출발지 예시·스키마·추천 스모크 테스트 (`node tests/core.test.js`) |

시드를 고친 뒤: `node tools/build.js && node tests/core.test.js`.
이미 쓰고 있는 브라우저에는 시드 변경이 자동 반영되지 않습니다 → 데이터 탭에서 import 하거나 "여행지만 시드로 초기화".

### 과거 기록 반영 방식 (schema v4)
기록 = **여행 맥락**(출발 전 근무, 이동수단, 운전 시간) + **평점 1~5**(장면별) + 기준선(기본 4) 넘을 때만 **이유**.
평점 3(보통)은 아무 데도 반영되지 않는다.

| 이유의 원인 | 반영 |
|---|---|
| 장소 | 축 가중치 배수 m(사양서 4절) + 이유에 연결된 여행지 속성(`attrs`)을 가진 곳 감점 |
| 근무 피로 | 이번 출발 전 근무가 기록과 같을 때만 감점 (예: N 직후 운전 피로 → N 직후 출발 시 차 필요한 곳 감점) |
| 일정·시기 / 컨디션 | 기록만, 점수 미반영 |
| 예약 선택 (숙소 소음·청결 등) | 점수 대신 추천 화면의 "예약할 때 체크" 팁 |

가점: 좋았던 이유에 연결된 속성(예: 먹을 곳 선택지 넓음), 숙소 유형별 평점, "특히 좋았던" 음식 종류 → 해당 여행지 가점(최대 0.5).
여행지 `attrs`에는 숙소·음식 **선택지 폭**(0~2)과 유형/종류 코드가 있다 (H 호텔 · R 리조트 · P 펜션 · K 한옥·게하 · C 캠핑 / S 해산물 · M 고기 · K 향토 · T 시장 · C 카페 · N 면·분식 · L 현지).
